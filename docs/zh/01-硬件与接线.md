## 一、选型理由

| 部件 | 为什么选它 |
|---|---|
| **ESP32-S3** | Wi-Fi 内置（不用外挂模块、不用再写一套串口协议）、240MHz 双核跑 LVGL 有余量、SDK 自带 lwIP / mbedTLS / NVS / OTA，这些都不用自己移植 |
| **ILI9341 2.8 寸 240×320** | 便宜、资料全的 SPI 屏；这个分辨率做信息看板够用，一帧又只有 153600 字节 |
| **XPT2046** | 与屏一体出货，和显示共用 SPI 总线，几乎不增加成本 |
| **SSD1306 128×32** | 独立常亮的副屏（时间、温度），主屏息屏时仍可读 |
| **MAX98357A** | I²S 功放，没有配置接口，接三根线就能响 |

**本模组的 PSRAM 不可用**：芯片 v0.2 版本片外 RAM 接口存在缺陷，开启后会出现随机数据错误。因此 `CONFIG_SPIRAM` 永久关闭，整个系统被限制在内部 SRAM 内运行。

## 二、引脚分配

### SPI 总线（SPI2）——显示与触摸共用

| 信号 | GPIO | 说明 |
|---|---|---|
| SCK | 21 | 40MHz |
| MOSI | 40 | 显示数据输出 |
| MISO | 35 | 触摸数据输入（显示从不读） |
| LCD_CS | 39 | 显示片选 |
| LCD_DC | 38 | 数据/命令选择 |
| LCD_RST | 37 | 显示复位 |
| TOUCH_CS | 36 | 触摸片选 |
| TOUCH_IRQ | 47 | 触摸中断（低有效） |

显示与触摸共用 SCK/MOSI/MISO，但**片选各自独立**。ESP-IDF 的 SPI 驱动会自动仲裁两个设备，每次传输是原子的。

> 触摸控制器的时钟（1MHz）远低于显示（40MHz），它是独立的 SPI 设备句柄，不从显示继承配置。

### I²C 总线（I²C0）——状态副屏

| 信号 | GPIO |
|---|---|
| SCL | 42 |
| SDA | 41 |

### 其他外设

| 功能 | GPIO | 说明 |
|---|---|---|
| 背光 PWM | 1 | LEDC，5kHz，8 位分辨率 |
| GPIO 输出 0~7 | 8、9、10、11、12、13、14、18 | 推挽，输入输出双向模式 |

### 为什么背光选 GPIO1

屏幕的 LED 引脚出厂直接接在 3V3 上，要 PWM 调光必须**把这根线改接到 GPIO**。选 GPIO1 的理由：

- 在右侧排针上，好接
- 普通 IO，不是 strapping 引脚（不会影响启动模式）
- 不占用 USB（D-/D+ 是 19/20）
- 不是板载灯（48）

## 三、供电

| 电源轨 | 负载 | 说明 |
|---|---|---|
| 5V | 输入，2A 适配器 | 供屏背光与功放 |
| 3.3V | ESP32-S3、OLED、触摸 | 由板载稳压器提供 |

**所有地必须共地。** 显示模块与主控之间地线悬空是"台面上好好的、装进壳子就花屏"的最常见原因。

## 四、显示之外的外设

### GPIO 输出

8 路配置为 `GPIO_MODE_INPUT_OUTPUT` 而不是纯输出模式。原因在于**引脚完好性自检**：纯输出模式下读回恒为 0，会把好引脚误判为损坏；输入输出双向模式才能读回真实电平。

判定依据（串口日志 `[gpiotest]`）：

| 结果 | 结论 |
|---|---|
| 引脚正常 + 释放后读回 1 | 引脚好、外部上拉好、模块供电正常（链路全通） |
| 引脚正常 + 释放后读回 0 | 引脚好但外部无上拉（模块没供电 / 上拉断 / 线没接） |
| 引脚异常 | 该 GPIO 大概率已被静电击穿，需换脚 |

### 音频

I²S 输出到 MAX98357A。音频链路已实现并用测试音验证过，但默认**不初始化**（`APP_AUDIO_TEST_TONE = 0`），可省下约 6KB 的 DMA 描述符。属于"不调用即零占用"的基础设施。

## 五、接线踩坑

| 现象 | 原因 |
|---|---|
| 白屏或随机花屏 | SPI 时钟对当前走线偏高，40MHz 退到 26MHz，再退 20MHz |
| 触摸坐标往边缘偏 | 电阻屏死区，需要线性校准（见下） |
| OLED 全黑且无报错 | I²C 地址不对（0x3C / 0x3D）或 SDA/SCL 接反 |
| 装壳后随机重启 | 供电不足或地线没共地 |

### 触摸校准

电阻屏的 ADC 输出范围与像素坐标不是线性对应，且边缘几毫米响应明显变差。四个校准常量定义**实际可用**的 ADC 窗口，再做线性映射并钳位：

```c
#define CAL_X_MIN   25
#define CAL_X_MAX   215
#define CAL_Y_MIN   25
#define CAL_Y_MAX   295

cx = (raw_x - CAL_X_MIN) * 240 / (CAL_X_MAX - CAL_X_MIN);
if (cx < 0) cx = 0;
if (cx >= 240) cx = 239;
```

不钳位的话，按边缘会算出屏幕外的坐标，LVGL 的命中测试会静默失败——表现为"点了没反应"。
